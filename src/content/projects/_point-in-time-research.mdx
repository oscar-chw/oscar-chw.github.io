### The problem

A backtest is only as honest as its inputs and its process. Data that was not yet known at the time (<Term t="look-ahead bias">look-ahead</Term>), a rule tweaked after seeing the test, or an AI assistant that grades its own idea can each make a weak strategy look strong. I wanted a research loop where code, not discretion, controls what data a study sees, when its rule is fixed, and who writes the numbers. In that loop, an LLM-proposed idea has to beat simple controls.

### What I built

- **A <Term t="point-in-time">point-in-time data layer</Term>.** Every read is as-of: a study at time *t* cannot see anything stamped after *t*.
- **<Term t="pre-registered">Pre-registered studies</Term>.** Each hypothesis becomes a method card, which is frozen and hashed together with its data before it runs. Any later tweak counts as a new trial.
- **A bounded AI role.** An LLM may draft hypotheses (without seeing prices) and a critic may object through a fixed schema. Neither can promote a result. Only the pre-registered rule decides.
- **A C++20 order-book replay engine** that reconstructs the book at any time *T*. It replaced the Python batch path, and parity is checked byte for byte.
- Two packages built on the same contract: the [Market-Making Lab](#market-making-lab) and the [Factor Lab](#factor-lab).

### Result

On a synthetic 100k-message benchmark, the C++20 replay is 25× faster than an optimized Python batch path, with byte-identical output and 47 tests. Called from Python, the whole path is 2.3× faster end to end.

- **The critic cannot promote.** A broken or adversarial critic can block a result but never pass one. The design accepts false negatives to rule out false positives.
- **The test data is sealed in code** until the gate, so a card that fails earlier never gets a test number to be tempted by.
- **The order book is a sorted vector, not a hash map**, because real books are shallow. Prices and sizes are integers, so parity with Python needs no tolerance.
- **The native path is opt-in**, because it accepts strictly less input than Python (it refuses fractional and NaN timestamps).

### Limits

- The replay benchmark is synthetic: one instrument and a shallow book. When the replay is called from Python, most of the time goes to the Python side and crossing the binding.
- No model has run the full loop yet: the LLM steps so far replay hand-written responses, so the loop is tested but the AI arm is not yet measured.
- Execution is idealized (flat cost, no slippage, borrow or funding), and the universe is a single market.
