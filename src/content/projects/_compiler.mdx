### The problem

A compiler has to turn source code into something a real toolchain accepts, with every corner of the language right: calls that return nothing, short-circuit evaluation with side effects, nested loops with break and continue, names that shadow other names.

### What I built

- **A compiler for a subset of SysY**, a C-like language, written in Java.
- **A visitor-based generator** that emits LLVM IR through the LLVM 13 C API, over an ANTLR4 grammar based on the course's.
- An individual course project. The code stays private under the course's rules, so this page describes it rather than linking it.

### Result

In a recorded post-course check, I added 12 extra test programs covering void calls, short-circuit side effects, nested break and continue, recursion, shadowing, hex and octal literals, and early returns. The check compared executable exit statuses against clang compiling the same source as C. It found a named call to a void function, which is invalid IR. After a two-line fix, the recorded run matched exit statuses for all 30 programs. This is historical evidence, not a fresh run or a comparison of full program output.

A subsequent local review rebuilt the compiler and checked LLVM verification, full return values against clang, diagnostics, and recovery after compilation or execution errors. A private local demonstration also exercised the path from source through LLVM to WebAssembly. This establishes the tested scalar subset in that local environment; it is not a hosted public compiler or a claim of complete language support.

### Limits

- Public case study only: the course solutions and grammar remain private.
- The fresh local suite passed, but stopping backend compilation after a browser Cancel remained an open issue in that reviewed candidate.
- Matching exit statuses does not establish matching stdout, full semantic equivalence or correctness for arbitrary programs.
- Array syntax is accepted by the grammar but is not implemented by the IR generator.
