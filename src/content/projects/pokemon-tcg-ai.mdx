## The problem

In this card game, the set of legal moves changes at every prompt and half the board is hidden. Kaggle runs the agent in a sandbox with no guarantee that PyTorch is installed. The hardest problem turned out not to be playing well. It was knowing that the agent running in the sandbox is the one that was trained.

## What I built

- **Policy learning** on 89,048 decisions from 926 games. The split is by game, so positions from a validation game never leak into training.
- **A set-transformer policy** that scores each legal option from typed board tokens, served with NumPy at inference so it does not depend on PyTorch.
- **Parity and packaging gates** that test the built package itself, not the training code.
- **A batched Rust/GPU simulator prototype** of a simplified game loop at about 110M steps/s, with the GPU output checked against a CPU reference.

## Limits

- The simulator is a prototype of a simplified game loop, not a full engine port.
- The final agent cannot be rebuilt from the repository alone: the weights, the game corpus and the licensed engine are not included.
