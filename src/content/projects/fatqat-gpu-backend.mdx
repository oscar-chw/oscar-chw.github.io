## The problem

A state-vector quantum simulator keeps every amplitude of the quantum state in memory and updates all of them for every gate. The state doubles with each added qubit, so larger circuits are limited by how fast the machine can move memory. FatQat, an open-source simulator by spaceqat, runs on the CPU. I wanted a GPU engine that existing FatQat code could use without changes and without losing accuracy.

## What I built

- **A CUDA (GPU) engine for FatQat** that sits behind the simulator's existing interfaces, so a circuit runs unchanged on either engine.
- **Double precision throughout**, matching the CPU engine rather than trading accuracy for speed.
- **A parity check against the CPU results**, so the engine is measured against the reference it replaces, not only for speed.

## Result

6× faster than a compiled multi-core CPU baseline at 24 qubits, within 8 machine epsilons of the CPU results. The figure was measured on engine revision r7; the current revision, r8, is faster.
