# Replace the theatrical gate

Oscar's direct feedback was verified in the coordinating chat's human message
`01a13a26-9ee2-77b2-a6e0-6cd8a7b99fba`: step 5 / Run gate does not reveal a real
mistake or useful execution. This is a substantive local revision, with a checked
preview before any new publication decision. Existing accepted releases remain
historical evidence.

## Concrete critique

At baseline `14591ed`, `exp/gatedbuild.ts` decides success from
`!(t.id === 4 && bug === "has a bug")`. No displayed pytest command runs. Reading
a chapter, extracting claims and obtaining a fresh review are unconditional
button transitions. Inputs, expected values and a real failing expression are
absent. The five separate clicks conceal rather than explain the work. The
synthetic label is truthful but insufficient: passing tests of this state machine
does not establish a useful visitor experience.

## Revised approach

Run `replay.admission.admit` from the **published** agentic-quant-research revision
`f8c48256e12b96523807ba8f59c04b798517e04e`, unchanged, in browser Python/WebAssembly.
The newer local repository commit is unpublished and is excluded. Retain the MIT
licence, source SHA256 pins and exact upstream code/test links.

Start with a visible, editable JSON-lines archive: a snapshot followed by an
aggregate-size update. Record 1 says received=21 ms but available=19 ms. The real
validator rejects it. Correct available to22 ms and the same validator produces
book rows; bid size becomes1 rather than4 because an update replaces the aggregate.
These are explicitly synthetic records adapted from the upstream test shapes,
not an exchange capture, a historical production incident or a performance claim.

One primary action runs the checks. Individual stages remain inspectable, but
their results come from reading/parsing input, loading hash-verified source,
calling the real function and inspecting its actual output. No pretend reviewer,
invented pytest output, fake progress delay or outcome controlled by a bug flag.
The scenario picker changes the input bytes; edited bytes determine the verdict.

Show the actual failure, clock fields and source line together; give a precise
correction and preserve before/after evidence. Show accepted rows and their
availability/continuity states, not only a green badge. Export the exact input,
source pins and returned result. Editing invalidates old results. Loading,
unavailable runtime, malformed input, reset, keyboard and narrow-screen states
must remain usable. A pass means this bounded archive passed this validator; it
does not authenticate clocks or prove a strategy or whole platform correct.

The project-page preview becomes a labelled build-computed example of the same
real Python failure/control pair. Project pages keep their existing script budget.
