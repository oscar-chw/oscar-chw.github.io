## Diagnosis and approach

There are 24 registered experiments, including four standalone pages. Several
already execute useful algorithms over visitor inputs. Others compute real maths
but expose only a preset toggle or random seed, hiding the records and decisions
that would make the engineering understandable. A green suite proves its named
assertions, not that all these experiences are complete.

Keep the liquid-glass shell, typography and established Astro stack. Make working
surfaces quiet and practical. Each tool needs an input, visible computation or
faithfully recorded measurement, an inspectable outcome, a consequential tradeoff,
and a reset. Use a small shared editor for similar text-data workflows, but preserve
the appropriate visual interaction: circuits, probability bars, timelines, graphs,
order ladders, surfaces and drawing canvases.

For constrained visual controls, a meaningful boundary case can replace a contrived
invalid text field. For recorded experiments, selection, source/method comparison
and export are useful; do not invent live execution. In every case explain the
limit. Public algorithms, synthetic examples and visitor-supplied data are distinct
from private production systems and from model performance claims.

Priority: editable timing/availability workflows, custom policy and calibration
cases, custom schedule entries, then inspectable market/race/filter/factor workflows
and recorded-study exploration. Retain useful existing implementations. Correct
overstated method labels, hidden-test leakage and silent boundary behavior where
the source audit exposes them.

## Acceptance

`coverage.json` enumerates the exact registry, actual source paths and per-demo
inputs, normal/boundary/repair/reset/provenance journeys. Initial states name gaps;
they do not certify completion. `check-demo-coverage.mjs` fails if a demo is absent,
a source/render record is missing, or a completed inventory retains unresolved
gaps or unverified changed workflows. Baseline visual captures are evidence of
layout only; they are not algorithm correctness tests.

Nodes67–69 add input/output regressions and run the existing related suites.
Node70 runs the unchanged full site checks plus all-demo browser/render coverage.
Changed algorithms must be checked against small hand-computable controls; malformed
input, stale results, repair, reset and export must have observable outcomes.
Keep original checks and their failures. Record exact source revision and test/render
scope. Physical-device and screen-reader use remain NOT_RUN unless actually performed.
